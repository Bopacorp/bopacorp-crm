# Phase 9 — Evidence and Execution Runbook

## Preconditions

1. Start the API in its test/development environment at
   `http://localhost:3000`.
2. Start the CRM at `http://localhost:5173` with
   `VITE_API_URL=http://localhost:3000/api/v1`.
3. Confirm that the database and test storage are available.
4. Load the five role credentials through an approved secret mechanism.
5. Confirm that the environment is not production.

The Playwright tests do not start or stop the API, CRM, database, or storage.
That lifecycle remains owned by the developer/operator running the local test.

## Checks before browser execution

```bash
npm run test:e2e:typecheck
npx biome check e2e playwright.config.ts
```

## Phase 9 execution

Run all mutable journeys with the role environment variables available in the
shell:

```bash
npm run test:e2e -- \
  e2e/mutations-crm.spec.ts \
  e2e/mutations-documents.spec.ts \
  e2e/mutations-catalog.spec.ts \
  e2e/mutations-employability.spec.ts \
  e2e/mutations-reports.spec.ts
```

Useful focused commands:

```bash
npm run test:e2e -- e2e/mutations-crm.spec.ts
npm run test:e2e -- e2e/mutations-documents.spec.ts
npm run test:e2e:report
```

The mutable suite uses Chromium, one worker, and a 90-second per-test timeout.
It does not require a coverage threshold.

## Artifact contract

The run may generate these ignored directories:

```text
playwright-report/
test-results/
```

Use the HTML report for the overall result. Use the per-test screenshots for
academic evidence and the trace/video only for diagnosis or explicitly selected
illustrations. Do not publish raw artifacts until they have been checked for
names, emails, business data, JWTs, storage paths, or other sensitive values.

## Evidence checklist

For each selected journey, retain at most three to five anonymized images:

- role-visible starting area;
- critical form or action;
- persisted success/state/history result;
- optional permission/error result.

Every image caption should state the case ID, role, action, expected result, and
observed result. The matrix names the screenshot generated by each journey.

## Full repository checks

The Phase 9 browser run is separate from repository quality gates. After the
focused mutable run, execute the normal checks:

```bash
npm run lint
npm run test:e2e:typecheck
npm run test:run
npm run build
```

Run the complete browser suite when all role variables and local services are
available:

```bash
npm run test:e2e
```

## CI handoff

Before making Phase 9 required in CI:

- provision an isolated database and storage bucket;
- seed deterministic lookup and role data;
- load credentials from CI secrets, never repository files;
- install Chromium dependencies;
- start API and CRM with readiness checks;
- run the full browser suite;
- upload `playwright-report/` and `test-results/` with `if: always()`;
- keep unit/API coverage thresholds independent from E2E pass/fail.
